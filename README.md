# 投資分析メモサイト

## 概要

日々の市場状況、注目銘柄、売買候補、リスク要因、ToDoを整理するためのシンプルなWebサイトです。

## 公開URL

GitHub Pagesで公開したサイトはこちらです。

https://hirotakahashijapan-dot.github.io/investment-memo-site2/

## 目的

このリポジトリは、GitHubの基本操作を練習するために作成しました。

また、投資判断の前提条件、買い理由、追加購入条件、撤退条件を明文化することで、感情的な売買を避け、後から判断の妥当性を振り返れるようにすることも目的としています。

主に以下の操作を学習します。

- リポジトリ作成
- ファイル作成
- コミット
- ブランチ作成
- Pull Request
- レビュー修正
- マージ
- 不具合修正

## 使用技術

- HTML
- CSS

## 現在の機能

- 今日の市場メモを表示
- 日次投資分析テンプレートを表示
- 今日のToDoを表示
- 複数ページ構成に対応
- トップページから注目銘柄、決算予定、売買判断メモ、リスク要因ページへ移動可能
- トップページにページ案内セクションを表示
- 注目銘柄、決算予定、売買判断メモ、リスク要因を専用ページで表示
- トップページはページ案内、市場メモ、日次投資分析テンプレート、ToDoに整理

## 今回追加した機能

### 保有状況ラベル表示

- 注目銘柄テーブルの「保有状況」をラベル風の見た目に変更
- 「保有中」と「監視中」で色を分け、状態を見分けやすく改善
- JavaScriptを使わず、HTMLとCSSのみで表示を調整

### 注目銘柄の保有状況列

- 注目銘柄テーブルに「保有状況」列を追加
- キオクシアを「保有中」、東京エレクトロンと旭化成を「監視中」として整理
- 銘柄ごとの保有状況と確認ポイントを同じ表で確認できるように変更

### ToDoチェックリスト表示

- トップページの「今日のToDo」セクションをチェックリスト風の表示に変更
- 各ToDo項目の前にチェックボックス風の見た目を追加
- JavaScriptを使わず、HTMLとCSSのみで表示を改善

### リスク分類テーブル

- リスク要因セクションを箇条書きから表形式に変更
- リスク分類、内容、影響を受ける銘柄、確認指標を表示
- マクロ、テーマ、市況、個別企業の観点でリスクを整理

### 注目銘柄テーブル

- 注目銘柄セクションをリスト形式から表形式に変更
- 銘柄名、ティッカー、注目理由、確認ポイント、優先度を表示
- 表を見やすくするためのCSSを追加

### 売買判断メモ

- 売買判断メモセクションを追加
- 対象銘柄、投資シナリオ、買い理由、追加購入条件、売却・撤退条件、確認すべきリスクを表示
- 横に広い表でも見やすいように、狭い画面向けのCSSを追加

### 決算予定

- 決算予定セクションを追加
- 銘柄名、ティッカー、決算予定日、決算前の注目ポイント、前回決算の評価、今回確認する項目、決算後の判断を表示
- 決算前後の確認ポイントを整理できるように変更

### 日次投資分析テンプレート

- 日次投資分析テンプレートセクションを追加
- 日付、市場環境、上昇要因、下落要因、注目銘柄、今日の判断、明日の確認事項を表示
- PCでは2列、スマホでは1列で見やすく表示されるようにCSSを追加

このテンプレートは、毎朝の相場確認で同じ観点を確認するために使います。  
市場環境、上昇要因、下落要因、今日の判断、明日の確認事項を同じ形式で記録することで、日々の投資判断を後から振り返りやすくします。

### 複数ページ構成

- `stocks.html`、`earnings.html`、`trade-notes.html`、`risks.html` を追加
- トップページに各ページへのナビゲーションリンクを追加
- 各専用ページに共通ナビゲーションを追加
- `style.css` にナビゲーション用CSSを追加
- GitHub Pagesで複数ページを公開できる構成に変更

### ページ案内セクション

- トップページにページ案内セクションを追加
- 注目銘柄、決算予定、売買判断メモ、リスク要因の各ページの役割を説明
- 各ページへ直接移動できるリンクを追加
- ページ案内をカード型レイアウトで表示
- スマホ表示では1列になるように調整

### トップページのシンプル化

- トップページから注目銘柄、決算予定、売買候補、売買判断メモ、リスク要因の詳細セクションを削除
- 詳細情報は専用ページで確認する構成に整理
- トップページはページ案内、市場メモ、日次投資分析テンプレート、今日のToDoに絞り込み
- 複数ページ構成に合わせて、トップページを入口として使いやすく変更

## 開発プロセス

このトレーニングでは、以下の流れで開発を進めます。

1. 要求仕様を整理する
2. 簡単な設計を行う
3. 初期実装を行う
4. ブランチを作成して機能追加する
5. Pull Requestを作成する
6. レビュー修正を行う
7. mainブランチにマージする
8. 不具合修正を行う
## 開発ルール

このリポジトリでは、GitHubの基本操作と開発プロセスを練習するため、以下のルールで作業します。

### ブランチ命名ルール

作業内容に応じて、以下の形式でブランチを作成します。

- `feature/...`：新機能を追加する場合
- `fix/...`：不具合修正や軽微な修正を行う場合
- `docs/...`：READMEなどドキュメントのみを修正する場合

例：

- `feature/add-stock-table`
- `feature/add-analysis-template`
- `fix/update-readme-future-tasks`
- `docs/add-development-rules`

### コミットメッセージルール

コミットメッセージは、変更内容が一目で分かるようにします。

良い例：

- `Add stock watchlist table`
- `Improve page design`
- `Update README for stock table feature`
- `Add daily analysis template section`

避けたい例：

- `修正`
- `更新`
- `test`
- `いろいろ変更`
